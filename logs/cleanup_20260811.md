# section_images 컬럼 미반영 버그 수정 (2026-08-11)

> 이전 이미지 중복 버그 수정(`logs/cleanup_20260805.md`)과도 별개 이슈. 별도 커밋/로그로 관리.

## 1. 신고 내용

`getting-glasses-in-korea-en` 글의 `articles.section_images` (jsonb, `{H2 제목: 검색어}`)
값이 실제 렌더링 이미지에 전혀 반영되지 않음. 렌더링된 이미지의 Unsplash ixid를
디코딩해보면 전혀 다른 검색어(예: 관광지 사진 검색어, 심지어 "japan" 문구)가 사용됨.

## 2. 원인

- `article.section_images` 컬럼을 읽는 코드가 프로젝트 전체에 **0건** (`grep -rln "section_images" src` 결과 없음)
- 실제 이미지 검색어는 `src/lib/images/smartImageSearch.ts`의 `getSectionImageKeywords()`가
  하드코딩된 정규식 패턴 딕셔너리(`placePatterns`)로 생성. 이 딕셔너리는 도쿄/오사카/교토 등
  일본 여행 콘텐츠 기준으로 작성되어 "안경/glasses/optical" 관련 패턴이 전혀 없고,
  `'예산|budget|비용|cost|가격'` 패턴 값에는 국가와 무관하게 `"travel budget planning japan expense"`가
  하드코딩되어 있음 (한국 글에도 그대로 적용됨)
- 매칭 패턴이 없는 나머지 섹션은 `${city} travel attraction landmark scenic` 기본 폴백으로
  전부 동일 문구가 됨 (city=seoul인 경우 5개 섹션 모두 "seoul travel attraction landmark scenic")
- 부가 문제: 이미 `entity_images` 캐시 테이블(`section-v4-*` 키)에 위 잘못된 검색어로 생성된
  이미지가 저장되어 있어, 검색어 로직만 고쳐도 캐시가 우선 조회되어 재현됨

## 3. 영향 범위 (신고 시점엔 몰랐던 부분 — 조사 중 확인)

`section_images`가 non-null인 아티클이 **257건** 존재. 즉 이 버그는 신고된 1건이 아니라
관리자가 `section_images`를 입력해둔 글 전부에 적용되던 문제. 단, 대부분은 컬럼이 비어있는
"기존 폴백 로직 그대로 사용" 글이라 이번 수정으로 인한 동작 변화가 없음 — 컬럼이 채워진
257건만 "저장해둔 검색어가 이제 실제로 반영됨"으로 개선됨 (회귀 아님, 의도된 수정 범위 내 효과).

참고: `sapporo-travel-guide-for-korean-travelers-2024` 등 일부 글은 `section_images`의 키에
`"## "` 접두사가 그대로 포함되어 저장되어 있어(`"## 주요 관광지"`), 파싱된 실제 heading(`"주요 관광지"`)과
문자열이 일치하지 않아 이번 수정으로도 반영되지 않음 — 코드 버그가 아니라 해당 글의 데이터 입력
형식 문제이며, 이번 스코프에서는 건드리지 않음 (기존과 동일하게 폴백 로직 사용).

## 4. 수정 내용

- `src/app/article/[slug]/page.tsx`, `src/app/en/article/[slug]/page.tsx`:
  - 섹션 이미지 캐시 키 버전 `section-v4-*` → `section-v5-*` (기존 잘못 캐시된 이미지를
    자연스럽게 무효화 — 별도 DB 삭제 작업 없이 다음 접근 시 새로 검색됨)
  - `getSectionImageKeywords()` 호출 전 `article.section_images?.[heading]`을 확인,
    값이 있으면 검색어 배열 맨 앞에 추가(`[manualKeyword, ...기존폴백쿼리]`) —
    Unsplash 검색이 실패할 경우를 대비해 기존 폴백은 그대로 유지
  - `section_images`가 비어있는 글은 `manualKeyword`가 `undefined`이므로 기존 로직과
    100% 동일하게 동작 (회귀 없음)

## 5. 검증

- `npx tsc --noEmit` — 통과
- `npm run build` — 프로덕션 빌드 성공
- DB 조회로 문제 아티클의 `section_images` 값 및 `entity_images` 캐시 내 잘못된 6개 행 확인
  (수정 스크립트로 직접 삭제하지 않고, 캐시 키 버전 상향으로 처리)

## 6. 범위 외

- `getSectionImageKeywords()`/`extractEntityFromSectionTitle()`의 하드코딩된 일본 중심
  패턴 딕셔너리 자체(예: "japan" 하드코딩)는 `section_images`가 비어있는 글들에는 여전히
  남아있는 잠재적 이슈. 이번 요청 범위는 "section_images 컬럼 미반영" 수정이었으므로
  패턴 딕셔너리 자체의 정확도 개선은 별도 이슈로 남겨둠.
- `"## "` 접두사가 포함된 `section_images` 키를 가진 소수 아티클의 데이터 정정은 미실행.
