# 섹션별 이미지 기능 완전 제거 (2026-08-12)

> 이전 이미지 관련 수정들(`cleanup_20260805.md`, `cleanup_20260811.md`)과도 별개 이슈. 별도 커밋/로그로 관리.

## 1. 배경

`section_images` 컬럼 미반영 버그(`cleanup_20260811.md`)를 고친 뒤에도, 배포 후 실사용 확인 중
같은 증상이 다른 글들에서 재발했다. 원인을 추적한 결과 코드 로직(우선순위) 문제가 아니라
**Unsplash Demo 키의 시간당 50건 검색 한도가 상시로 소진**되는 것이 근본 원인이었다.
한도 초과 시 새 검색어(섹션별로 다른 검색어)는 전부 실패하고, 예전에 이미 캐시된 적 있는
범용 패턴 검색어(`${city} travel attraction landmark scenic` 등)만 우연히 재사용되면서
"본문과 무관한 사진이 계속 나온다"는 증상이 반복적으로 재현됐다.

추가로 확인된 사실: 한도가 리셋된 직후에도 몇 번의 요청만으로 다시 0/50까지 소진됨 —
운영 중인 사이트의 실시간 트래픽(커버 이미지 없는 글 방문 시 실행되는 hero 폴백 로직 포함)이
같은 키를 상시 사용 중이라는 뜻. 섹션별 이미지 기능은 구조적으로 신뢰할 수 없다고 판단.

## 2. 결정

섹션별(`## ` 헤딩마다) Unsplash 이미지 기능을 아티클 렌더링 경로에서 완전히 제거.
페이지 상단 대표 이미지(`cover_image_url`, 없으면 제목 기반 하나의 hero 이미지) 한 장만 사용.

## 3. 변경 내용

- `src/app/article/[slug]/page.tsx`, `src/app/en/article/[slug]/page.tsx`:
  - `getSectionImage`(sectionImageResolver), `getSectionImageKeywords`/`fetchUniqueUnsplashImage`/
    `getCachedSectionImage`/`cacheSectionImage`(smartImageSearch) import 및 호출 전부 제거
  - `sectionPhotos` 계산 블록, `<figure>` 섹션 이미지 렌더링 블록 삭제
  - 히어로 이미지 로직(`cover_image_url` 있으면 그대로, 없으면 `fetchUnsplashPhoto(getSectionImageKeyword(...))`)은
    유지 — 이번 스코프는 섹션별 이미지만 해당, 대표 이미지 생성 방식은 변경하지 않음
  - `getSectionImage`, `getSectionImageKeywords` 등 함수 자체는 삭제하지 않음 (호출부만 제거,
    다른 곳에서 참조 여부는 확인하지 않았으므로 보존)

## 4. 검증

- `npx tsc --noEmit` — 통과
- `npm run build` — 프로덕션 빌드 성공

## 5. 커버 이미지 백필 (별도 진행 중)

`cover_image_url`이 비어있던 5개 글 중 `getting-glasses-in-korea-en` 1건만 완료
(Unsplash 재검색 → `cover_image_url`/`cover_image_attribution` UPDATE, 히어로 로직과 동일한
`getSectionImageKeyword()` 함수 재사용). 나머지 4건(`kpop-idol-makeup-seoul-en`,
`jjimjilbang-korean-spa-seoul-en`, `kimono-rental-kyoto-en`, `momos-coffee-busan-en`)은
Unsplash 한도 소진으로 중단, 추후 별도 진행.

## 6. 범위 외 / 후속 논의 필요

- Unsplash API 가이드라인이 요구하는 다운로드 트래킹 호출(`GET /photos/:id/download_location`)이
  `src/lib/unsplash.ts`, `src/lib/images/*` 어디에도 없음을 확인 — 기존부터 있던 컴플라이언스
  공백이며 이번 작업 범위는 아니지만 별도로 다룰 필요가 있음.
- Unsplash Demo 등급(시간당 50건) → Production 등급(시간당 5,000건) 신청은 계정 소유자만
  가능한 외부 작업이라 별도 안내함.
